# BiliLens — B站视频 AI 精读

把 B站的长视频变成**带时间戳的结构化笔记**。打开视频页 → 点一下 → 几分钟后得到一份可跳转、可检索、可入库的 Markdown 笔记。

**核心特点：不用下载视频，不用填 Cookie，不用配置任何 B站 相关的东西。**

---

## 它是怎么做到「一键」的

大多数同类工具的工作流是：下载视频 → 提取音频 → 语音转文字 → 总结。慢、占空间、还容易失败。

BiliLens 走的是另一条路，分三层拿素材：

| 优先级 | 素材来源 | 成本 | 说明 |
| --- | --- | --- | --- |
| ① | **B站官方 AI 总结** | 免费、即时 | 官方已生成的「摘要 + 分章提纲 + AI 字幕全文」，一次请求全拿到 |
| ② | **视频字幕** | 免费、即时 | 人工字幕优先，其次 AI 字幕 |
| ③ | **本地极速 ASR 转写** | 本地免费、极速 | 针对无字幕生肉视频，调度本地 GPU 运行 Fun-ASR-Nano (0.8B) 极速转录 |

前两层能覆盖绝大部分常规视频（秒级响应）。当遇到没有字幕的生肉视频时，BiliLens 会无缝联动内置的本地 ASR 服务完成高精度转写与带时间戳字幕生成。

拿到的素材再交给你自己配置的大模型做「二次创作」——重新组织表达、按章节提炼要点、保留时间戳。

### 为什么不需要填 Cookie

B站的内容接口要求三件事同时成立：登录 Cookie、WBI 签名、正确的来源。

主流做法是在扩展里伪造这三样，既麻烦又容易被风控拦。

BiliLens 的做法是**把请求放在 B站页面的上下文里发**（MV3 的 `world: "MAIN"` 内容脚本）：

- `fetch api.bilibili.com` 属于同站请求 → Cookie 自动携带
- Referer / Origin 天然正确，无需伪造
- WBI 签名在本地计算（纯 TS 实现，无第三方依赖）

所以**你在浏览器里登录了 B站，插件就是登录态**，不用做任何额外操作。

## 安装

### 1. 构建

```bash
pnpm install
pnpm build          # 产物在 .output/chrome-mv3
```

### 2. 加载到浏览器

1. 打开 `chrome://extensions`
2. 右上角开启「开发者模式」
3. 点「加载已解压的扩展程序」，选择 `.output/chrome-mv3` 目录

> 需要 Chrome / Edge **116 或更高版本**（侧边栏 API 的要求）。

### 3. 配置模型

点插件图标 → ⚙ 进入设置页，填入你的 API 地址与密钥：

| 项 | 示例 |
| --- | --- |
| API 地址 | `https://api.siliconflow.cn/v1` |
| API 密钥 | `sk-...` |
| 模型名称 | `Qwen/Qwen2.5-72B-Instruct` |

内置了硅基流动、DeepSeek、Moonshot、智谱、OpenRouter、OpenAI、Ollama 等预设，也可以填任意自建/中转端点——**只要它兼容 OpenAI 的 `/chat/completions` 协议**。

**模型不用手打**：填好地址、授权域名之后，插件会自动拉取该端点的模型列表，
在下拉框里直接选。拉不到（有些中转站不实现 `/models`）时可以手动填。

**可以保存多份配置**：点「+ 新建配置」再配一份，例如云端一份、本地网关一份。
点一下即可切换，切换立刻生效，不用每次重填密钥。

**思考深度**（`reasoning_effort`）：留空 = 模型默认；选了档位才发送该参数。
只对支持思考的模型有意义，网关不认识时忽略它，没有副作用。

> 首次连接某个域名时，浏览器会要求授权该域名的访问权限。点一下「授权域名」即可。

#### 图像输入

聊天框里可以直接 **Ctrl+V 粘贴截图**提问。截图会先缩到最长边 1280px 再发出去，
既省 token 也不容易撞上端点的请求体上限。

插件无法判断某个模型是否支持看图（同一个端点下不同模型能力不同），
所以设置页里有一项「支持图像输入」，需要你按当前模型明确打开。
没打开就粘贴图片时，插件会直接提示你去哪里打开，而不是静默把图片丢掉。

### 4. 本地 ASR 极速语音识别服务（生肉无字幕视频必用）

如果视频没有任何官方或 AI 字幕，BiliLens 可联动本地专属推理服务进行**亚秒级语音转文字**：
- **模型架构**：通义实验室最新 Fun-ASR-Nano (0.8B)，自带时间戳与标点，仅占用约 1GB 显存。
- **默认端口**：`18765`。

#### 启动本地服务：
```powershell
cd server

# 首次运行：自动高速下载模型权重 (~942MB)
python download_models.py

# 启动服务（Windows 一键启动）
.\start-server.ps1
```
服务启动后保持常驻（`http://127.0.0.1:18765`），遇到生肉视频时点击「生成笔记」，插件将展示实时进度条（包含第几段、实时百分比与剩余预估耗时）并直接完成总结！详见 [`server/README.md`](server/README.md)。

## 使用

1. 打开任意 B站视频页
2. 点插件图标 → 侧边栏识别当前视频，显示素材状态
3. 面板里有两个页：

### 目录

点「生成笔记」，笔记流式出现。**点任意时间戳即可让视频跳到对应位置**。

顶部视频卡片上有**字幕下载**按钮（有字幕时出现）：SRT / VTT / 纯文本三种格式，
官方总结自带的字幕零等待直接下，字幕轨来源的会自动采集后再下。

### 聊天

不用先生成笔记，打开就能问——它读的是这个视频的完整字幕。
回答里的时间戳同样是可点的，点了视频跳过去。

一个视频可以有**多段对话**：顶部下拉切换，点「＋」新建，× 删除当前对话。
比如先问整体脉络，再单独开一段逐节追问，互不干扰。

如果模型输出了**思考过程**（`reasoning_content`，DeepSeek 系 / 各类本地网关常见），
回答上方会出现一个默认折叠的「思考过程」块，想看点开即可。
不发任何额外请求参数，模型不思考就什么都不显示。回答末尾会以小字显示
本轮 token 用量（输入/输出，端点返回了才有）。

底部有一个「播放位置」开关：

- **默认关闭**。多数问题是关于整个视频的（「它到底想说明什么」），
  带上播放位置反而会让模型误以为你在问当前这一段。
- 想问「这里讲了什么」时打开它，提问会附带当前进度。

聊天记录按视频保存，关掉面板再打开还在。**图片不落盘**（base64 很占空间，会撑爆浏览器配额），
重载页面后原来的图片位置会显示「已不再保留」。

### 存入 Obsidian

设置页里选择你的 Obsidian 库目录，笔记就会直接写进去（不是下载到 Downloads 再手动搬运）。

生成的 Markdown 带 YAML frontmatter：

```yaml
---
title: "视频标题"
up: "UP主"
source: https://www.bilibili.com/video/BV...
bvid: BV...
created: 2026-02-14T15:04:05.000Z
model: "deepseek-chat"
tags:
  - bilibili
  - 视频笔记
---
```

这样可以配合 Dataview 按 UP主、标签做聚合检索。

## 技术栈

| 层 | 选型 | 为什么 |
| --- | --- | --- |
| 构建 | **WXT 0.21** + Vite 8 | 三个候选里唯一活跃维护的（Plasmo 已停滞 15 个月）；原生支持 `world: "MAIN"` |
| 语言 | **TypeScript 5.9.3** | 见下方说明 |
| UI | **Vue 3** `<script setup>` | 有 4 个 UI 入口，需要组件复用与模板类型检查 |
| 测试 | **Vitest 5** | 175 个单元测试 + 端到端验证脚本（见 `AGENTS.md`） |

### 为什么 TypeScript 锁 5.9.3 而不是最新的 7.x

TypeScript 7（Go 重写的原生编译器）确实更快，但 `vue-tsc@3.x` 依赖 TS 编译器内部路径 `./lib/tsc`，而 TS 7 不再导出该路径，会导致 **`.vue` 文件的模板类型检查完全失效**。

实测报错：

```
Error [ERR_PACKAGE_PATH_NOT_EXPORTED]: Package subpath './lib/tsc'
is not defined by "exports" in typescript/package.json
```

参见 [vuejs/language-tools#6124](https://github.com/vuejs/language-tools/issues/6124)。因此这里主动选择 5.9.3，**用最新版反而是错的**。

## 项目结构

```
bililens/
├── entrypoints/
│   ├── background.ts          # Service Worker：仅做轻量协调
│   ├── bridge.content.ts      # 【MAIN world】在页面上下文调 B站 API
│   ├── relay.content.ts       # 【ISOLATED】页面 ↔ 扩展的双向中继
│   ├── sidepanel/             # 侧边栏 UI
│   └── options/               # 设置页 UI
├── lib/
│   ├── wbi.ts                 # WBI 签名 + 自实现 MD5（无依赖）
│   ├── bilibili.ts            # B站接口客户端
│   ├── llm.ts                 # LLM 流式客户端 + SSE 解析器 + 提示词
│   ├── markdown.ts            # 自写渲染器（先转义再生成标签，防 XSS）
│   ├── export.ts              # 导出下载 / 直写 Obsidian
│   ├── storage.ts             # 设置持久化 + 运行时域名授权
│   ├── time.ts                # 时间与文件名工具
│   └── types.ts               # 领域模型 + 类型化消息协议
├── components/                # Vue 组件
├── tests/                     # 单元测试
└── scripts/                   # 图标生成 + 两套验证脚本
```

### 两个关键架构决策

**1. LLM 调用放在侧边栏，不放 Service Worker。**

MV3 的 Service Worker 会在约 30 秒空闲后被强制回收。长视频的流式总结往往要跑 1~3 分钟，放在 SW 里必然中途断掉。侧边栏是有 DOM 的扩展页面，生命周期跟随可见状态，不会被无故回收。

**2. 分两个世界注入内容脚本。**

`MAIN world` 才能拿到页面的同源身份（Cookie + Referer 正确），但它访问不到 `chrome.*` API；`ISOLATED world` 反过来。所以两边各司其职，通过 `window.postMessage` 通信。

## 验证

```bash
pnpm check           # 类型检查 + 单元测试 + 构建（日常只需这一条）

# 可选：需要真实浏览器 / 真实网络的验证
pnpm e2e             # 端到端：扩展加载 → 注入 → 真实调用 B站接口
pnpm verify:live     # WBI 签名是否被 B站服务端接受
pnpm shot            # 给选项页与侧边栏截图（同时检查底栏不透明等样式契约）
pnpm shot:components # 用真实 Vue 组件渲染导轨/聊天/空态并截图
pnpm prompt chat     # 打印发给模型的提示词原文（note / chat）
```

`pnpm e2e` 会验证：扩展加载 → 后台启动 → MAIN world 注入 → 真实调用 B站接口取到数据 → 扩展页面可加载。

`pnpm shot:components` 用 Vite 编译**真实的 .vue 组件**再截图，因此图里的每个时间戳胶囊、每根导轨连线都来自线上代码。同时断言：导轨节点与等宽时间戳已渲染、Tab 只有两个且名称正确、聊天里的时间戳带 `data-seek`（可点）、播放位置开关状态反映到 UI、用户消息有气泡而助手消息没有。

### 覆盖到的关键测试

- MD5 与 RFC 1321 标准向量逐条比对，包含跨 64 字节块的边界长度
- **复现 B站官方文档给出的示例签名** `1073871926b3ccd99bd790f0162af634`
- SSE 流式解析：逐字符喂入模拟最恶劣的网络分块
- Markdown 渲染的 XSS 防护：`<script>`、`<img onerror>` 均只作纯文本
- 嵌套列表的标签闭合正确性（拍平即失效）
- **笔记与聊天共享素材**：字幕只抓一次，聊天不重复下载
- **播放位置默认不发送**，且只附在最后一条用户消息上，不污染历史
- 多标签页不串台（面板只认自己绑定的那一页）

## 已知限制

- **无字幕视频无法处理。** 目前只能覆盖有官方总结或有字幕的视频（约七成）。没有任何字幕的视频需要本地 Whisper 转写，尚未实现。
- **番剧/影视支持有限。** 走了 PGC 接口取基础信息，但官方总结接口对其支持不完整。
- **总结质量取决于你的模型。** 插件只负责把素材整理好并给出结构化提示词，不保证输出质量。
- **B站接口随时可能变更。** WBI 混淆表或必需参数一旦调整，需要同步更新 `lib/wbi.ts`。`scripts/verify-live.mjs` 可快速确认签名是否仍然有效。
- 需要 Chrome 116+，`--load-extension` 在 Chrome 137+ 已移除（本项目的 e2e 脚本已改用 CDP `Extensions.loadUnpacked`）。

## 隐私

- 所有 B站 数据在**你的浏览器内**获取和解析，不经过任何第三方服务器。
- API 密钥只保存在本机浏览器存储中。
- 只有「生成笔记」这一步会把你选中的视频素材发给你**自己配置的**模型服务。
- 不收集任何遥测数据。
